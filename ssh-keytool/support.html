SSH Keytool — Support

Generate, convert and inspect SSH keys and certificates — 100% offline in your browser.

Using SSH Keytool

  • Install SSH Keytool from the Chrome Web Store, or use the web version.
  • Click the toolbar icon to open the popup, then pick a tab: Generate, Derive, Cert, Convert or FIDO.
  • Use the Copy buttons to copy keys, commands and snippets. Nothing is saved, so copy what you need before you close the popup.

Common questions

Can SSH Keytool create a FIDO (ed25519-sk / ecdsa-sk) key?

No. A FIDO key is created on the security key itself, which a browser can’t do for SSH. Use FIDO › Command Builder to get the ssh-keygen command, run it with your security key plugged in, then paste the result into FIDO › Inspect Key to check it.

macOS says “No FIDO SecurityKeyProvider specified”

The ssh-keygen that ships with macOS has no FIDO support. Install a FIDO-enabled OpenSSH, for example with Homebrew (brew install openssh), and run its ssh-keygen instead.

Why can’t I convert my FIDO key?

A FIDO private key file is only a handle for the security key and exists only in OpenSSH format. To change its passphrase, run ssh-keygen -p -f <file>.

I chose PKCS#1 with a passphrase, but got PKCS#8

Encrypted PKCS#1 is non-standard, so SSH Keytool writes an encrypted PKCS#8 key instead and shows a note. PKCS#1 is also RSA-only: Ed25519 and ECDSA keys can’t be exported as PKCS#1.

Why is there a warning when I encrypt to PuTTY PPK?

PPK v2 protects the key with a weak, unsalted SHA-1-based scheme. Prefer OpenSSH or PKCS#8 if the software you use accepts them.

My encrypted FIDO key file won’t unlock

SSH Keytool supports the aes128/192/256-ctr and aes128/192/256-cbc ciphers (ssh-keygen uses aes256-ctr by default). chacha20-poly1305@openssh.com and AES-GCM aren’t supported yet, and neither are FIDO certificates (sk-*-cert-v01@openssh.com).

Are my keys sent anywhere?

No. SSH Keytool makes no network requests and stores nothing. See the Privacy Policy.
